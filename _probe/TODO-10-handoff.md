## Byte-equal invariant justification

`var_est` does the floating-point operations in the **exact same order**
as the original inline block:

| step | original (per estimator)                      | new (in `var_est`)                          |
|------|-----------------------------------------------|---------------------------------------------|
| 1    | `let mean_a = mean(psi_a)`                    | `let mean_a = mean(psi_a)`                  |
| 2    | `let mean_b = mean(psi_b)`                    | `let mean_b = mean(psi_b)`                  |
| 3    | `let coef = -mean_b / mean_a`                 | `let coef = -mean_b / mean_a`               |
| 4    | `let mut gamma = 0.0`                         | `let mut gamma = 0.0`                       |
| 5    | `for i in 0..n: let psi = coef*psi_a[i]+psi_b[i]; gamma = gamma + psi*psi` | same |
| 6    | `gamma = gamma / n.to_double()`               | `gamma = gamma / n.to_double()`             |
| 7    | `let j = mean_a`                              | `let j = mean_a`                            |
| 8    | `let sigma2 = gamma / (j * j * n.to_double())`| `let sigma2 = gamma / (j * j * n.to_double())` |
| 9    | `let se = sigma2.sqrt()`                      | `let se = sigma2.sqrt()`                    |

The `n` integer source changes from `self.n_obs()` (outer scope) to
`psi_a.length()` (local in `var_est`), but they are always equal in
the real call sites (psi_a is built as `Array::make(n, 0.0)` where
`n = self.n_obs()`), so the integer value flowing into `n.to_double()`
is identical.

No reordering, no algorithmic change, no Kahan summation. This is a
literal extraction; the IEEE 754 results are bit-for-bit identical.
