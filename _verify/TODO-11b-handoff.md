## Notes / smells flagged but not addressed

- **LPQ coef regression**: the post-fix IPW bisection converges to
  theta ≈ 1.48 instead of 1.4999. This is a finite-sample
  difference in the bisection root, not a bug in the math; the
  population median of `y | d=1` is 1.49, which both values
  bracket. If higher precision is needed for downstream code that
  compares LPQ to PQ at the decimal level, the fix is to add a
  centering correction to the IPW score (the upstream Python
  port does NOT do this either — both bisection approaches have
  the same O(1/n) bias on small samples). Documented as a known
  limitation in the `lpq_within_5pct_of_pre_fix` test.
- **PQ `deriv` derivative at the bisection boundary**: the
  numerical derivative `d mean(score) / d theta` is computed via
  the central difference at `theta +/- h`, where `h = (ymax-ymin)*1e-2`.
  For very flat outcomes (`y` is concentrated), `h` may be smaller
  than machine epsilon, in which case `deriv = 0` and the SE is
  NaN. The current DGP doesn't trigger this (well-spread `y`),
  but it's a TODO #11c edge case.
- **Cross-fit counter is global**: the `g_cross_fit_count` spy is
  a package-level `Ref[Int]`, so tests that run in parallel
  would interfere. The current `moon test` runs sequentially so
  this is fine, but it's a fragile API. Marked as a TODO #11c
  refactor target (pass a counter into `solve_pq` instead of
  using a global).
- **QTE covariance depends on DGP**: for the canonical location
  shift DGP, the cross-covariance between `psi_d1` and `psi_d0`
  is small and positive, so the new QTE SE is barely different
  from the buggy quadrature SE (0.088134947 vs 0.088156080,
  ~0.02% difference). For DGPs where the two arms have very
  different `m` or fold assignments, the new SE can differ by
  much more. The `qte_se_hand_computation` test pins the new
  formula to 1e-9 and would catch any future regression.
