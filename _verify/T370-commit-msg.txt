Release 0.36.0: build_row_unit_map abort -> raise ClusterDataError

Continuing the surgical abort -> raise conversion pattern from
v0.35.0 (where var_est_cluster's J-floor defensive guard was
converted). This release tackles the second silently-skipped
panic_* test in the cluster-DML stack: build_row_unit_map's
missing-unit defensive guard.

  - kfold.mbt: declare pub suberror ClusterDataError with
    MissingUnit(Int) variant (carries the missing unit id).
  - kfold.mbt::build_row_unit_map: signature `Array[Int]` ->
    `Array[Int] raise ClusterDataError`; the abort is replaced
    with `raise ClusterDataError::MissingUnit(g)`.
  - 5 fit_cluster methods (plr/irm/pliv/iivm/plpr) wrap each
    build_row_unit_map call in
    `try ... catch { ClusterDataError::MissingUnit(g) => abort(...) }`
    to preserve the pre-v0.36.0 process-death behavior. Public
    API unchanged.

The pre-v0.36.0 panic_build_row_unit_map_missing_unit test was
silently skipped on native/wasm-gc (MoonBit's panic_* driver
skips panic-prefixed tests; see _verify/WHITEBOX_T_REPORT.md).
The test is renamed to build_row_unit_map_raises_missing_unit
and rewritten using the `try ... catch ... noraise` pattern
introduced in v0.35.0:

  try build_row_unit_map(malformed_cluster, uniq) catch {
    ClusterDataError::MissingUnit(g) => inspect(g, content="5")
  } noraise {
    _ => fail("expected build_row_unit_map to raise MissingUnit on unit_id=5")
  }

The noraise branch fails the test if no error fires (catches
any future mutation that bypasses the raise). The catch branch
asserts the exact variant + payload (catches mutations that
construct a different variant or strip the payload).

Verified: silencing the raise (replacing it with `let _ = g`)
makes the test fail with the expected diagnostic message. The
test is now a real assertion that runs on every backend.

Public API stability: DoubleMLXXX::fit and DoubleMLXXX::fit_cluster
signatures unchanged. From outside, the API behaves identically
to v0.35.0. Internally, the cluster helper stack now raises two
domain-specific suberror types (VarEstClusterError + ClusterDataError),
each documented at the top of kfold.mbt.
