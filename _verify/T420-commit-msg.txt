Release 0.41.0: array_min / array_max abort -> raise EmptyArrayError

Continuing the surgical abort -> raise conversion pattern from
v0.35.0-v0.38.0. This release tackles two more defensive aborts
in the quantile stack.

  - kfold.mbt: declare pub suberror EmptyArrayError (no
    payload).
  - quantile.mbt::array_min / array_max: signatures
    `Double` -> `Double raise EmptyArrayError`. Functions
    changed from `fn` to `pub fn` so the regression tests
    can exercise them directly. The `abort("array_min:
    empty array")` (line 4) and `abort("array_max: empty
    array")` (line 18) calls are replaced with
    `raise EmptyArrayError`.
  - quantile.mbt::solve_pq: no signature change. The
    internal `array_min`/`array_max` calls (line 177,178)
    are wrapped in `try ... catch { EmptyArrayError =>
    abort("solve_pq: empty y array (data.y.length() == 0)") }`
    to preserve the pre-v0.41.0 process-death behavior.
  - DoubleMLLPQ::fit: the `array_min`/`array_max` calls
    (line 156,157) are wrapped in
    `try ... catch { EmptyArrayError => abort(...) }` to
    preserve the pre-v0.41.0 process-death behavior.

New regression tests (all in quantile_test.mbt):
  - array_min_raises_on_empty: calls array_min([]) and
    asserts the error fires via
    `try ... catch ... noraise { fail(...) }`.
  - array_max_raises_on_empty: same pattern for array_max.
  - array_min_max_returns_correct_values_on_nonempty:
    guards against a regression where the raise conversion
    accidentally changes the success path.

Mutation-verified: replacing `raise EmptyArrayError` with
`let _ = ()` (silenced raise) makes the regression tests
fail with the expected diagnostic (process death, caught by
the test runner).

Public API stability:
  DoubleMLPQ::fit, DoubleMLQTE::fit, DoubleMLCVAR::fit,
  DoubleMLLPQ::fit signatures are unchanged. Internally,
  the solve_pq / array_min / array_max calls now wrap in
  `try ... catch { EmptyArrayError => abort(...) }` to
  preserve the pre-v0.41.0 process-death behavior. From the
  outside, the API behaves identically.
