## MoonBit-side contract (`cmd/main/main.mbt` output)

The Python validators depend on moonbit-coder having added, for **each
of the 5 estimators** (PLR, IRM, PLIV, IIVM, DID), an extra section in
`moon run cmd/main` output, after the existing n_rep=1 block:

```
=== MoonBit DML {NAME} (n_rep=5) ===
estimated theta (n_rep=5) = ...
se (n_rep=5) = ...
```

where `{NAME}` is `PLR`, `IRM`, `PLIV`, `IIVM`, or `DID` (no `(partialling
out)` / `(ATE score)` / `(LATE score)` / `(observational score)` suffix —
just `{NAME}` + `(n_rep=5)`). The theta line uses `estimated theta`
universally, including for IIVM (which the n_rep=1 block labels as
`estimated LATE`).

Per-estimator parser regexes (defined inside each validator):

```
_NREP5_SECTION_HEADER_RE = re.compile(r"===\s*MoonBit DML {NAME}[^\n]*n_rep=5[^\n]*===")
_NREP5_THETA_RE          = re.compile(r"estimated\s+theta\s*\(n_rep=5\)\s*=\s*([0-9.eE+-]+)")
_NREP5_SE_RE             = re.compile(r"se\s*\(n_rep=5\)\s*=\s*([0-9.eE+-]+)")
```

## MoonBit-side aggregation formula

The MoonBit-side `n_rep=5` section is generated by `aggregator.mbt:32-60`
(see `aggregator.mbt:32-60` for the canonical contract):

```
theta_hat = median(theta_1..R)
ub_r      = theta_r + 1.96 * se_r          for each rep r
se_hat    = (median(ub_1..ub_R) - theta_hat) / 1.96
```

The Python `moonbit_aggregate_coef_se(coefs, ses)` helper in each
validator is a literal byte-equal mirror of this formula
(including the `n == 1` fast path `(coefs[0], ses[0])`).

## Per-rep K-fold

Each rep `r` uses an **independent** K-fold split:
`KFold(n_splits=2, shuffle=True, random_state=3141 + r)`.
This is the statistical-equivalent of the MoonBit-side chacha8 +
Fisher-Yates `kfold(n_obs, n_folds=2, seed=3141 + r)`. We do not
attempt to bit-replicate the MoonBit RNG — the test passes
statistically (within `2 * SE` of each other), not bit-exactly.

## `high_median` helper

Each validator carries a small `high_median(arr)` helper that
returns `sorted(arr)[len(arr) // 2]`, i.e. the **upper** (high)
median. This is the same selector MoonBit's `aggregator.mbt:32-60`
uses (`coefs_sorted[n / 2]` for `theta_hat`, `ub[n / 2]` for
`ub_hat`), so for even `n` the Python and MoonBit sides agree
that "median" means the upper-middle element, not numpy's default
lower-middle.
