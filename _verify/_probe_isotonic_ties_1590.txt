PORT (measured, probe_isotonic_tied_x):
  pava([0,1])                    = [0, 1]          <- correct: y is already monotone
  fit_isotonic([.5,.5],[0,1]).x  = [0.5, 0.5]
  fit_isotonic([.5,.5],[0,1]).yhat= [0, 1]          <- WRONG, should be [0.5, 0.5]
  predict_isotonic               = [1, 1]          <- WRONG, should be [0.5, 0.5]
  adjust_ps(isotonic, clip .01)  = [0.99, 0.99]    <- THE REPORTED SYMPTOM
  fit_isotonic 3 ties y=[0,1,0]  = [0, 0.5, 0.5]    <- WRONG, should be [1/3]*3
  fit_isotonic distinct x        = [0, 0.5, 0.5]    <- matches sklearn (control passes)

ROOT CAUSE
  fit_isotonic runs pava over the RAW sorted sequence without first pooling
  observations that share the same x. Isotonic regression is a function of x,
  so two observations at the same x MUST receive the same fitted value; sklearn
  groups equal x and takes the group mean before the pool-adjacent-violators
  step. Because predict_isotonic resolves a tie to the LAST index of the run,
  the port reports the final y in each tie run -- and with clip=0.01 that 1.0
  becomes 0.99.

PROPERTY THAT MAKES THE FIX SAFE
  With all-distinct x every group has size 1 and its mean is exactly y[i], so
  pooling is the identity and pava sees the identical sequence. The fix is a
  no-op on tie-free data, which is why the existing parity fixtures (float
  propensity scores, no exact ties) did not catch this.
