Release 0.45.0: transform_panel dead-code abort — documented + diagnostic improved

This release tackles `plpr.mbt:447` (the `transform_panel`
else-branch abort for an unknown approach) but recognizes
it as dead code, mirroring the v0.37.0 pattern for
`did_multi.mbt:558` (p_adjust fallback).

Why the abort is dead code:
  - `DoubleMLPLPR::new` (line 479-484) has a `require()`
    that checks `approach` is one of
    {cre_general, cre_normal, fd_exact, wg_approx}.
  - `transform_panel` is only called from
    `DoubleMLPLPR::fit` (line 550), which only sees
    approaches that passed the `::new` require.
  - The abort can only fire if a caller constructs
    `DoubleMLPLPR` directly via struct literal (the
    struct is `pub`), bypassing the `::new` require.

Changes:
  - plpr.mbt::transform_panel: abort message improved
    from "DoubleMLPLPR: unknown approach \{approach\}"
    to
    "DoubleMLPLPR: unknown approach (set in DoubleMLPLPR::new): " + approach.
    v0.45.0 also adds a comment block above the abort
    explaining the dead-code contract.
  - CHANGELOG: documents the dead-code status and
    cross-references v0.37.0's did_multi.mbt:558 skip.
