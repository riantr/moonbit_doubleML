Release 0.43.0: DoubleMLDIDData::new binary-check abort -> raise DIDDataError

Continuing the surgical abort -> raise conversion pattern from
v0.35.0-v0.42.0. This release tackles the non-binary-treatment
defensive guard in DoubleMLDIDData::new (did.mbt:27).

  - kfold.mbt: declare pub suberror DIDDataError with
    NonBinaryTreatment(Int) variant (carries the first
    non-binary index as payload).
  - did.mbt::DoubleMLDIDData::new: signature
    `DoubleMLDIDData` -> `DoubleMLDIDData raise DIDDataError`.
    The `abort("DoubleMLDIDData.d must be binary {0, 1}")` is
    replaced with `raise DIDDataError::NonBinaryTreatment(i)`.
  - 3 prod callers wrap in try/catch/re-abort to preserve
    pre-v0.43.0 process-death behavior:
    - did_binary.mbt:343 (`DoubleMLDIDBinary::new`, the
      placeholder `DoubleMLDIDData` with all-zero `d`)
    - did_binary.mbt:507 (`DoubleMLDIDBinary::fit`, the
      wide-format `d` from `preprocess_did_binary`)
    - cmd/main/main.mbt:232 (the cmd demo)

New regression test (did_test.mbt):
  - did_data_raises_on_non_binary_treatment: calls
    `DoubleMLDIDData::new` directly with a 3-row
    `d = [0.0, 0.5, 1.0]` (entry 1 is non-binary) and
    asserts the error fires with `i == 1`. Uses
    `try ... catch ... noraise { fail(...) }` pattern.
    Mutation-verified: removing the validation loop
    (replacing the `if d[i] != 0.0 && d[i] != 1.0 { raise ... }`
    block with `if false { raise ... }`) makes the test
    fail with the expected diagnostic.

Public API stability:
  DoubleMLDIDData::new is the only signature change. All
  callers that previously got process-death now get the
  same process-death via the try/catch/re-abort pattern,
  so the externally observable behavior is identical.
