Release 0.38.0: isotonic_calibrate_cv abort -> raise CalibrationFittingError

Continuing the surgical abort -> raise conversion pattern from
v0.35.0/v0.36.0/v0.37.0. This release tackles `isotonic_calibrate_cv`'s
malformed-cv-partition defensive guard.

  - kfold.mbt: declare pub suberror CalibrationFittingError with
    IncompleteCVPartition variant (no payload).
  - ps_processor.mbt::isotonic_calibrate_cv: signature
    `Array[Double]` -> `Array[Double] raise CalibrationFittingError`.
    The malformed-cv-partition abort is replaced with
    `raise CalibrationFittingError::IncompleteCVPartition`.
    Function is now `pub` (was `fn`) so the regression test can
    exercise it directly.
  - ps_processor.mbt::apply_calibration: signature
    `Array[Double] raise InvalidCalibrationError` ->
    `Array[Double] raise Error` so the catch block in
    PSProcessor::adjust_ps can handle both the unknown-method
    error (v0.37.0) and the incomplete-partition error (v0.38.0).
    A wildcard arm `_ => abort("apply_calibration: unknown error")`
    is added to satisfy MoonBit's `partial_match` warning.
  - PSProcessor::adjust_ps: catch block gains a second arm for
    CalibrationFittingError::IncompleteCVPartition that re-aborts
    with the pre-v0.38.0 message.

New regression test:
  isotonic_calibrate_cv_raises_incomplete_partition constructs a
  malformed cv partition (5 inputs, one fold covering only 4 of
  them) and asserts the error fires via the
  `try ... catch ... noraise { fail(...) }` pattern.

Mutation-verified: replacing the raise with `()` silently makes
the test fail with the expected diagnostic.

Public API stability:
  PSProcessor::adjust_ps signature unchanged. From outside, the
  API behaves identically.
