Score, derivative, aggregation, start value, point estimate and variance
formula all match. The root finder does not, and that is the deviation the
clamp comment already owns.

The 0/300 figure from 13c was about to be thrown out. It fitted upstream
with LogisticRegression(C=1e6) while the port defaults to
LogisticRegression::new(), which reads like a C = 1.0 default, so the two
sides of the comparison would have had different regularization and "upstream
is robust where the port is not" would have been an artifact.

It is not. LogisticRegression in this port has no regularization parameter
at all -- { fitted: false, coef_: [] } at logistic.mbt:23-25, no C, no
penalty, no lambda. It is an unregularized MLE, the same regime as C=1e6.
The configurations match in substance and the figure stands.

A sweep written to "fix" this by forcing upstream to C = 1.0 was deleted
rather than kept: it would have introduced the very mismatch it claimed to
remove. Second time in this series an experiment was caught before it
produced a number by checking its premise first; the first was the 0-anchor
d_tilde probe.

What remains unexplained is narrower than 15c implied but is real: upstream
is 0/300 non-finite on this DGP and the port's Newton diverges by trial 2,
with every element above checked. The clamp stays and small-n stays
reported rather than gated.
