Release 0.46.0: DoubleMLDIDMulti::p_adjust dead-code abort — documented + diagnostic improved

This release tackles `did_multi.mbt:574` (the
`DoubleMLDIDMulti::p_adjust` match fallback abort) but
recognizes it as dead code, mirroring the v0.37.0 and
v0.45.0 patterns.

Why the abort is dead code:
  - `DoubleMLDIDMulti::p_adjust` has a `require()` (lines
    548-561) that covers all 11 valid method names
    (romano-wolf, rw, holm, bonferroni, bh, by, fdr_bh,
    fdr_by, tsbh, tsby, fdr_tsbh, fdr_tsbky).
  - The match (lines 565-573) covers exactly the same set.
  - The `_ =>` arm can only fire if a caller bypasses the
    public API (e.g. via struct literal). The `require`
    aborts first if a caller passes an unknown method.

Note: did_multi.mbt:1145 (draw_bootstrap_weights) was
already converted in v0.37.0 to `raise BootstrapMethodError`.
The regression test draw_bootstrap_weights_raises_unknown_method
was added in v0.37.0. No further work needed.

Changes:
  - did_multi.mbt::DoubleMLDIDMulti::p_adjust: abort message
    improved from
    "DoubleMLDIDMulti::p_adjust: unknown method"
    to
    "DoubleMLDIDMulti::p_adjust: unknown method (set in DoubleMLDIDMulti::p_adjust): " + method_name.
  - v0.46.0 also adds a comment block above the abort
    explaining the dead-code contract and cross-referencing
    v0.37.0, v0.42.0, and v0.45.0 dead-code skips.
