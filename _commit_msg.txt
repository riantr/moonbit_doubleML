gitignore: cover the .archived_<date> scratch-rename suffix

The verifier / cleanup cycle has been using a dated archive
suffix (`<name>.archived_<YYYY_MM_DD>[_<seq>]`) for ephemeral
session-scratch renames since the v0.50+ cleanup rounds. The
existing `.gitignore` covers the bare `.archived` and
`.archived.<ext>` patterns but not the dated variant, so 18
untracked files (session-scratch from the v0.52 release and
its follow-ups) were showing up in `git ls-files
--others --exclude-standard` even though they are clearly
scratch by name.

Added a single new pattern `*.archived_*` that catches both
files and directories with the dated suffix:

  _add_licenses.py.archived_2026_09_24
  _commit_msg.txt.archived_2026_09_24{,_b.._g}
  _ddebug.archived_2026_09_25/{main.mbt,moon.mod,moon.pkg}
  _fix_examples_names.py.archived_2026_09_24
  _gen_cmd_moon_mod.py.archived_2026_09_24
  _rename_examples.py.archived_2026_09_24
  _stale_root_files.txt.archived_2026_09_25
  _syntax_test.archived_2026_09_25/{main.mbt,moon.pkg}
  _test_t1.txt.archived_v2

Before: `git ls-files --others --exclude-standard` showed 18
        rows; root felt cluttered; `git status` had a long
        noise list.
After:  same query returns 0 rows.

The 13 already-gitignored variants (`*.archived`,
`*.archived.*`, `_verify/*.archived*`) are unchanged.

Verification:
  - git check-ignore -v <sample files>        : all match
    the new `*.archived_*` rule (line 31)
  - git ls-files --others --exclude-standard  : 0 rows
  - moon check --deny-warn                     : exit=0,
    0 diagnostic warnings (unchanged from 3965c11)

No public API changes; no library code touched. Single-line
gitignore edit, four-line comment explaining the dated-suffix
convention.
