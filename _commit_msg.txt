global-review: tighten CI Python loop + sync estimator/example counts in docs

A follow-up to aec880d (which fixed 4 critical bugs found by the
v0.52 post-release global review). This commit clears the
documentation and CI-loop drift surfaced by the same review, plus
tracks 7 verifier-produced docs that were sitting untracked.

(a) .github/workflows/check.yml — CI step name corrected and
    loop tightened. The python-cross-check job was titled
    "Run all 9 validate_*.py scripts" and the loop body was
    `python "$s" | tail -1`, which:
      - reported the wrong count (9, not the actual 23+1);
      - never asserted the trailing line contained `PASS`,
        so any script that crashed silently exited 0
        (the same gap B2 revealed for the master
        `validate_with_python.py`).

    Renamed the step to "Run all 23 validate_*_with_python.py
    scripts" and replaced the loop with one that:
      - captures the trailing line into a variable;
      - fails the job (`exit 1`) with an `::error::` annotation
        if any script's trailing line doesn't contain `PASS`;
      - still prints the line so the success case is greppable.
    The 23 prefixed scripts already follow the convention
    (per `skills/moonbit_doubleML.md`); the master script that
    didn't is now `.archived`.

(b) Estimator count wording — the same drift in three places:
      - README.md line 5 said "covering all 16 models";
      - line 12 said "Models ported | 17 / 17";
      - line 100 said "17 models";
      - the Models table listed 19 rows.
    On disk we have 22 `DoubleML*` structs in 17 files
    (some files hold 2 structs: apo.mbt has APO+APOS,
    quantile.mbt has PQ+QTE, blp_policy.mbt has BLP+PolicyTree).
    19 mirror upstream doubleml-for-py; 3 are MoonBit extras
    (DoubleMLDIDCSBinary, DoubleMLLPLR, DoubleMLPLPR).
    Rewrote:
      - the top-line claim to say "all 19 models in upstream
        ... plus 3 MoonBit-specific extras";
      - the Status table to "22 DoubleML* structs in 17 files";
      - the Models table to 22 rows with `(upstream)` /
        `(extra)` markers, including the 3 previously-omitted
        entries (PLPR, LPLR, DIDCSBinary).

(c) Example count wording — three counts in the same repo
    (14 dirs on disk, 13 in moon.work before aec880d, 14 after,
    plus README/AGENTS.md said 13 or 12 depending on context).
    Updated:
      - README "Demo entry points" header to "14 dirs, all in
        moon.work; 13 run end-to-end + 1 library-user pattern";
      - the Drivers table to add `did_cs_binary` (was already
        there, but now tagged `DoubleMLDIDCSBinary`), replace
        `examples/lplr | DoubleMLLPQ` (wrong: lplr.mbt is
        `DoubleMLLPLR`, not LPQ) with the corrected entries;
      - README "Project layout" section to "14 driver binaries
        (all listed in moon.work)";
      - AGENTS.md "moon.work members" to "16 total" and
        "examples/<bin>/` × 14";
      - skills/moonbit_doubleML.md estimator list to 22
        entries (with the 3 extras) and "14 driver binaries".
