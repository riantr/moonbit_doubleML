_typos.toml: whitelist 5 domain terms / variable names that typos flagged

The v0.53.0 publish.yml re-trigger (after the moon-fmt fix
landed) cleared "Check formatting" but failed at "Check typos":
46 false positives across the codebase. The previous version
of _typos.toml only whitelisted 6 terms (apos, ndout, pava,
CAUSAL, DML, dml). Five more needed:

  - compliers / complier / Complier
      Imbens-Angrist IV terminology. In LATE / IRM / LPQ
      code paths and their docs, "complier" = "subject who
      takes the treatment they were assigned to". Not a
      misspelling of compiler.
  - iy
      Internal LPQ variable name (in-sample index for the
      bisection search in `lpq.mbt`). Looks like a typo of
      "it" but is intentional.
  - lik
      Inner-product accumulator in `linalg.mbt::cholesky`.
      Local short variable; not meant to be "like".
  - unparseable
      Valid English spelling (Merriam-Webster + Wiktionary).
      The codebase uses both spellings; this is the
      canonical form in error messages.
  - mis
      3-letter column abbreviation in the v0.x release-table
      (mis | fix | summary), aligned vertically. Not a typo
      of "miss" / "mist".

All 5 are pure extend-words additions; no source code
changes. After this commit:

  typos --files . | wc -l          # = 0
  moon fmt --check                 : exit=0
  moon check --deny-warn           : exit=0, 0 diagnostic warnings
  moon test --target native        : 401 / 401

After this commit + tag push, the publish.yml workflow
should clear all gates including the typo check, then
proceed to "Publish to Mooncakes" and "Create GitHub
Release".
