kfold: add whitebox tests for cluster-aware fold expansion

The library previously had 0 whitebox tests (`*_wbtest.mbt`).
All 390 tests were blackbox (`*_test.mbt`), exercising only
the public surface (`Fold`, `kfold`, `kfold_stratified`,
`slice_*`). Two package-internal helpers were unreachable from
the blackbox side:

  - `expand_unit_folds_to_rows(cluster, folds_u, row_unit)` —
    the cluster-aware fold expansion used by every
    clustered-DML path (PLR, IRM, PLPR, PLIV, IIVM cluster-
    robust fits). Its contract is structural: every row of a
    unit lands on the same side of every split, the per-fold
    unit count equals the unit-level test fold size, and the
    total row coverage is complete. None of these were tested
    directly.

  - `build_row_unit_map(cluster, uniq)` — the row → unit-
    position lookup. Its contract is correctness under
    non-contiguous unit ids (real panel data has firm ids
    like {3, 5, 7, 11}, not {0, 1, 2, 3}). The v0.36.0
    ClusterDataError::MissingUnit path was untested at the
    helper level.

This commit adds `kfold_wbtest.mbt` with 5 tests covering:

  1. `expand_unit_folds_to_rows_partition_is_row_complete` —
     every row 0..n-1 appears exactly n_folds times across
     all folds (once in test_indices of the fold where its
     unit is selected for test, once in train_indices of the
     other folds). For 2 folds, every row is visited twice.

  2. `expand_unit_folds_to_rows_no_unit_straddles_split` —
     for each fold, for each unit, the intersection of
     `row_unit == u` with `test_indices` is either empty or
     all-of-u. This is the cluster contract.

  3. `expand_unit_folds_to_rows_fold_n_units_matches_unit_fold` —
     the third return value equals `folds_u[f].test_indices().length()`.

  4. `build_row_unit_map_non_contiguous_unit_ids` —
     unit ids {3, 5, 7, 11} map positionally to {0, 1, 2, 3}.

  5. `build_row_unit_map_raises_on_missing_unit` —
     a cluster id not in `uniq` raises
     `ClusterDataError::MissingUnit` (v0.36.0 path).
