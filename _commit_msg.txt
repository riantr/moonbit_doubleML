Ran `moon fmt` on the whole workspace. 95 files were rewritten;
the changes split into two classes:

  - 79 real reformatting changes (signature re-alignment,
    trailing commas, whitespace inside blocks, single-line
    array literals where moon fmt prefers them, etc.). These
    are real stylistic changes that the v0.52+ toolchain
    expects.

  - 16 CRLF-only / trailing-newline changes (mostly "no
    newline at end of file" that moon fmt now adds). These
    are byte-only changes that do not affect semantics; they
    live in:
      - doc/00X_*/moon.pkg (6 files)
      - doc/moon.mod
      - examples/consumer_demo/{main.mbt, moon.mod, moon.pkg}
      - moon.work
      - moonbit_doubleML/{dgp_did_SZ2020_test.mbt,
        dgp_pliv_cluster_test.mbt, dgp_plpr_test.mbt,
        matrix_wbtest.mbt, p3_did_utils_parity_test.mbt}

Both classes are needed for `moon fmt --check` to pass; the
CRLF-only changes aren't gitignorable at HEAD but ARE in the
"formatted" state once committed.

Not reverted per the memory-note B12 "CRLF revert" pattern:
the strategy applies to commits where HEAD is already in the
formatted state and the working tree was just bloated with
whitespace noise. In this case HEAD is NOT in the formatted
state, so all 95 changes must land.
